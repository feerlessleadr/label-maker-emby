## Label Maker 0.1.6.0 (albums shown as Ready are filed when dry run is turned off)

### What is fixed
- **Turning dry run off now files the albums that were already shown as *Ready (dry run)*.** In 0.1.5.0 and earlier those albums stayed in Ready forever, even after dry run was switched off and **Check inbox now** was pressed; the only way out was to open each album on the Albums tab and press the filing button. Now the next check puts every Ready album that you have not decided about yourself back in line, and files it by the same rules as a new album (a certain match, every file fits, no close rival, the lane allows it, the destination is free). An album that no longer qualifies goes to the review list with the reason.
- Nothing else changed: matching, the settings page and the routes are as in 0.1.5.0.

### Still true
This is a trial build that **starts in dry run**. Install and first steps: `docs/INSTALL-TRIAL.md`.

### How it was tested
304 unit tests, including a new one that shows an album in Ready under a dry run and then filed once dry run is off; the live test (49 checks) on a private, throw-away Emby 4.10 instance, including the settings page script loaded in a real browser. The page itself is unchanged since 0.1.4.0.

### Known limits
Unchanged: no cover art download, no keep-both or replace choice for an album already in the library, no special handling of classical music or audiobooks.

### Verify the download
`LabelMaker.dll.sha256` has the SHA-256. The file also carries a signed build attestation: `gh attestation verify LabelMaker.dll --repo feerlessleadr/label-maker-emby`
