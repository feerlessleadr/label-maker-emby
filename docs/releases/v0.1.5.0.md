## Label Maker 0.1.5.0 (events subscription for the phone app)

### What is new
- **Events subscription over Emby's websocket.** The Embidextrous app subscribes with `{"MessageType":"LabelMakerEventsStart","Data":"0,30000,<afterSeq or empty>,<access token>"}` and receives `{"MessageType":"LabelMakerEvents","Data":{"ApiLevel":1,"LatestSeq":n,"Truncated":false,"Events":[...]}}`: once on subscribing (the events after `afterSeq`, or only a baseline when it is empty), within about a second of every new alert, and as an empty heartbeat every 30 seconds. Only administrators can subscribe; the token in the start message is checked through Emby's session manager and is never logged. This is what lets the app receive alerts, because Emby's "send to administrator sessions" does not reach a socket that keeps its token in a header. Details: `docs/NOTIFICATIONS.md` section 12.
- Nothing else changed: matching, filing, the settings page and the routes are as in 0.1.4.0.

### Still true
This is a trial build that **starts in dry run**. Install and first steps: `docs/INSTALL-TRIAL.md`.

### How it was tested
303 unit tests; 49 live checks on a private, throw-away Emby 4.10 instance, including the subscription connected the way the app connects (token only in the `X-Emby-Token` header and in the start message, never in the address): baseline, a regular user and an unknown or missing token refused, alerts pushed in order and once each, the heartbeat, replay from a number, and a check that no token appears in any log or file; plus the settings page script loaded in a real browser.

### Known limits
Unchanged: not yet tried on a production server with network shares, no cover art download, no keep-both or replace choice for an album already in the library, no special handling of classical music or audiobooks.

### Verify the download
`LabelMaker.dll.sha256` has the SHA-256. The file also carries a signed build attestation: `gh attestation verify LabelMaker.dll --repo feerlessleadr/label-maker-emby`.
