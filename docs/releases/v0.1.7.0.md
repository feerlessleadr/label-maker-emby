## Label Maker 0.1.7.0 (cover art)

### What is new
- **Cover art for albums that have none.** After an album is filed (by itself or by your choice on the Albums tab), if its library folder holds no `cover`, `folder` or `albumart` image, Label Maker asks the Cover Art Archive (coverartarchive.org) for the front cover of the edition it used (500 pixels wide, the size your Picard uses) and saves it as `cover.jpg` next to the music, where Emby looks for it. A cover that came with the download or was already in the library is never replaced. The image is checked to really be a JPEG or a PNG. If the release has no cover, or the archive cannot be reached, the album is filed all the same.
- **Undo removes the cover Label Maker added**, and only that one.
- **A switch:** Settings > Naming and tags > *Download cover art for albums that have none* (on by default). Only the album's MusicBrainz release id is sent to the archive; turn the switch off and nothing is sent there. The Albums tab says "Cover art added." when it happened.
- The picture is not written into the files' tags.

### Still true
This is a trial build that **starts in dry run**. Install and first steps: `docs/INSTALL-TRIAL.md`.

### How it was tested
310 unit tests (six are new: the download address and image checks, a cover added, an existing cover kept, no cover on the archive, Undo removing it); the live test (49 checks) on a private, throw-away Emby 4.10 instance, and the settings page opened and used by hand in a browser. **Not yet seen:** a real download from coverartarchive.org on your server; the first album you file with the switch on is that check.

### Known limits
No keep-both or replace choice for an album already in the library, no special handling of classical music or audiobooks, no cover art embedded in the tags, no second try when the archive has nothing.

### Verify the download
`LabelMaker.dll.sha256` has the SHA-256. The file also carries a signed build attestation: `gh attestation verify LabelMaker.dll --repo feerlessleadr/label-maker-emby`
