## Label Maker 0.1.8.0 (files already in the library, and a fix for tracks that arrive later)

### What is fixed (please update)
- **Tracks that arrived later in a folder that was already filed are now filed.** MusicGrabber downloads track by track, so a folder can receive more tracks after the first ones were filed. In 0.1.7.0 and earlier those tracks were marked as filed but were **never moved**: they stayed in the inbox. Now they are matched and filed like any new album. Albums that an older version left that way are checked again by themselves on the next check (about a minute after Emby starts the plugin). Each batch keeps its own undo record: Undo puts back the latest batch, and the next Undo steps back one more.

- A small fix on the Label Maker page: a status timer that kept running after Emby threw the page away printed an error in the browser console every five seconds. It now stops by itself.

### What is new
- **Keep both or replace, for an album with files already in the library.** Open the album (it shows as *Already in library*) on the Albums tab, press **See what is already in the library**, and the preview shows which files are there and the size of the library copy next to yours. Then choose:
  - **Keep both:** the new copy gets a number after its name ("1-02 Brat (2).mp3"); nothing in the library is touched.
  - **Replace the old files:** each old file is first saved in the inbox's `_Replaced` folder (nothing is deleted), then the new one takes its place.
  - **Undo** works for both. For replace it puts the old files back and removes the empty `_Replaced` folders. If you deleted the saved old files yourself, Undo stops before moving anything and says so.
- Label Maker still never chooses for you: an automatic check leaves such an album waiting, as before.

### Still true
This is a trial build that **starts in dry run**. Install and first steps: `docs/INSTALL-TRIAL.md`.

### How it was tested
325 unit tests (three of them fail without the fix for the later tracks; nine cover keep both, replace, undo and a cut-off in the middle of replacing); the live test (57 checks, eight new) on a private, throw-away Emby 4.10 instance, and the Albums tab used by hand in a browser (Already in library, keep both, replace and Undo for each). **Not yet seen:** these on your own server and library.

### Known limits
No "file only the new tracks and leave the duplicates" choice for an album that overlaps partly, no special handling of classical music or audiobooks, no cover art embedded in the tags.

### Verify the download
`LabelMaker.dll.sha256` has the SHA-256. The file also carries a signed build attestation: `gh attestation verify LabelMaker.dll --repo feerlessleadr/label-maker-emby`
